# day-entries Specification

## Purpose

달력의 특정 날짜에 일정이나 근무 변경(휴가·대체근무)을 세부 내용으로 기록하고, 그 내용이 그날 근무와 달력 칸 표시에 반영되도록 한다.

## Requirements

### Requirement: 날짜 화면 열기
달력의 날짜 칸(인접 월 칸 포함)을 누르면 그 날짜의 화면이 SHALL 열린다. 날짜 화면은 날짜, 그날 근무, 세부 내용 목록, [추가] 버튼을 표시한다.

#### Scenario: 날짜 칸 누르기
- **WHEN** 달력에서 `2026-10-20` 칸을 누른다
- **THEN** 2026년 10월 20일 화면이 열리고 그날 근무와 세부 내용 목록(없으면 빈 상태 안내)이 표시된다

### Requirement: 세부 내용 항목 구성
세부 내용 항목은 이름(필수, 1~20자), 시작·종료 시간(선택, `HH:MM`), 내용(선택, 최대 500자), 분류(선택, 근무 유형 6종 중 하나)로 SHALL 구성된다. 이름이 비었거나 길이 제한을 넘으면 저장할 수 MUST 없다.

#### Scenario: 이름만 입력
- **WHEN** 이름 "병원 예약"만 입력하고 저장한다
- **THEN** 시간·내용·분류 없이 항목이 저장된다

#### Scenario: 이름 없음
- **WHEN** 이름을 비운 채 저장하려 한다
- **THEN** 저장할 수 없고 이름을 입력하라는 안내가 표시된다

### Requirement: 시간 입력 규칙
시간은 시작만, 또는 시작과 종료를 함께 SHALL 입력할 수 있다. 종료만 입력해서는 MUST NOT 되며, 종료가 시작보다 이르면 다음 날 종료로 해석해 "다음 날"로 표시한다.

#### Scenario: 시작~종료
- **WHEN** 시작 09:00, 종료 18:00으로 저장한다
- **THEN** 항목에 "09:00~18:00"이 표시된다

#### Scenario: 자정 넘김
- **WHEN** 시작 22:00, 종료 07:00으로 저장한다
- **THEN** 항목에 "22:00~다음 날 07:00"이 표시된다

#### Scenario: 종료만 입력
- **WHEN** 시작 없이 종료만 입력한다
- **THEN** 저장할 수 없고 시작 시간을 입력하라는 안내가 표시된다

### Requirement: 하루 여러 항목
한 날짜에는 세부 내용을 여러 개 SHALL 작성할 수 있다. 목록은 시작 시간이 있는 항목을 시간순으로 먼저, 시간이 없는 항목을 작성 순서로 뒤에 표시한다.

#### Scenario: 정렬
- **WHEN** 같은 날에 "회식"(19:00), "병원"(10:00), "택배"(시간 없음)를 순서대로 작성한다
- **THEN** 목록은 병원, 회식, 택배 순서로 표시된다

### Requirement: 세부 내용 수정과 삭제
날짜 화면에서 항목을 누르면 편집 화면이 열려 모든 값을 SHALL 수정할 수 있고, 삭제할 수 있다. 삭제는 확인 후 실행되어야 한다(MUST).

#### Scenario: 수정
- **WHEN** "병원" 항목의 이름을 "치과"로 바꿔 저장한다
- **THEN** 날짜 화면과 달력 칸에 바뀐 이름이 반영된다

#### Scenario: 삭제 확인
- **WHEN** 항목 편집 화면에서 삭제를 누르고 확인한다
- **THEN** 항목이 사라지고 날짜 화면으로 돌아간다

### Requirement: 그날 근무 변경
분류를 가진 항목이 있는 날의 근무는 반복 패턴 대신 그 분류로 SHALL 결정된다. 분류를 가진 항목이 여러 개면 사용자가 날짜 화면에서 고른 항목의 분류를, 고른 적이 없거나 고른 항목이 분류를 잃었으면 가장 먼저 작성한 항목의 분류를 쓴다. 반복 패턴과 다른 날짜의 근무는 바뀌지 않아야 한다(MUST).

#### Scenario: 휴가로 변경
- **WHEN** 패턴상 야간인 날에 분류 "휴무"인 항목 "연차"를 저장한다
- **THEN** 그날 근무가 휴무로 표시되고 전날·다음 날 근무는 패턴대로이다

#### Scenario: 여러 분류 기본값
- **WHEN** 같은 날에 분류 "당직" 항목을 먼저, 분류 "휴무" 항목을 나중에 작성한다
- **THEN** 그날 근무는 당직이다

#### Scenario: 적용 항목 선택
- **WHEN** 위 상태에서 날짜 화면에서 "휴무" 항목을 그날 근무로 고른다
- **THEN** 그날 근무가 휴무로 바뀌고 앱을 다시 열어도 유지된다

#### Scenario: 분류 제거
- **WHEN** 그날 근무를 정하던 유일한 분류 항목을 삭제하거나 분류를 없앤다
- **THEN** 그날 근무가 반복 패턴의 근무로 돌아간다

### Requirement: 달력 칸 표시
세부 내용이 있는 날짜 칸은 근무 글자 아래에 첫 항목(정렬 기준) 이름의 앞글자를 SHALL 표시하고, 항목이 2개 이상이면 `+n`(나머지 개수)을 덧붙인다. 근무가 세부 내용으로 바뀐 날은 바뀐 근무 글자와 함께 변경 표시(점)를 보여야 한다(MUST).

#### Scenario: 이름 앞글자
- **WHEN** 어떤 날에 "병원" 항목 하나만 있다
- **THEN** 그 칸에 근무 글자와 "병"이 표시된다

#### Scenario: 여러 항목
- **WHEN** 어떤 날에 항목이 3개 있고 첫 항목 이름이 "병원"이다
- **THEN** 그 칸에 "병+2"가 표시된다

#### Scenario: 변경 표시
- **WHEN** 분류로 근무가 바뀐 날을 본다
- **THEN** 바뀐 근무 글자와 변경 표시 점이 함께 보인다

### Requirement: 세부 내용 저장
세부 내용은 설정과 별도인 로컬 저장소 키 `turncal.entries`에 `version`을 포함한 JSON으로 SHALL 저장되고 앱을 다시 열어도 유지된다. 이 키가 손상되면 설정·달력은 정상 표시하고 세부 내용만 불러오지 못했다고 안내하며, 사용자가 새로 저장하기 전까지 기존 값을 덮어써서는 MUST NOT 된다.

#### Scenario: 재실행 유지
- **WHEN** 세부 내용을 저장하고 앱을 다시 연다
- **THEN** 같은 항목과 그날 근무 변경이 그대로 표시된다

#### Scenario: 세부 내용 손상
- **WHEN** `turncal.entries` 값이 손상된 상태로 앱을 연다
- **THEN** 달력은 반복 패턴대로 표시되고 세부 내용을 불러오지 못했다는 안내가 보이며 저장값은 그대로이다

#### Scenario: 저장 실패
- **WHEN** 세부 내용 저장 중 저장소 쓰기가 실패한다
- **THEN** 편집 화면에 머무르며 입력 내용이 유지되고 오류가 안내된다
