# schedule-export Specification

## Purpose
보고 있는 달의 근무를 달력 이미지와 캘린더 파일로 만들어 기기의 공유 창으로 보내, 사용자가 턴캘 밖(메신저·드라이브·캘린더 앱 등)에서 근무표를 보여 주거나 옮길 수 있게 한다.

## Requirements

### Requirement: 내보내기 진입점
현재 근무 패턴이 있으면 달력 화면은 하단 바로가기 줄 아래에 [이번 달 내보내기] 버튼을 SHALL 표시한다. 현재 패턴이 없으면 버튼을 표시해서는 MUST NOT 된다. 버튼을 누르면 "달력 이미지 보내기"와 "캘린더 파일 보내기" 두 선택지가 있는 바텀시트가 열리고, 바텀시트는 파일이 기기의 공유 창으로 열려 카카오톡·드라이브 등 보낼 곳을 고르게 된다는 점을 안내하고, "캘린더 파일 보내기"에는 공유 창에 캘린더 앱이 없을 수 있으므로 나와의 채팅·드라이브 등으로 보낸 뒤 받은 파일을 열면 캘린더 앱에 추가할 수 있다는 안내를(읽기 쉽게 두 줄로) SHALL 함께 보여 준다. 바텀시트는 뒤로가기나 닫기로 아무것도 보내지 않고 닫힌다. 배너 광고와 그 위 마지막 조작 요소 사이 간격 규칙은 이 버튼에도 적용된다.

#### Scenario: 버튼 표시
- **WHEN** 근무 패턴이 있는 상태로 달력 화면을 연다
- **THEN** 바로가기 줄 아래에 [이번 달 내보내기]가 보인다

#### Scenario: 패턴 없음
- **WHEN** 근무 패턴이 없는(첫 실행·패턴 초기화 뒤) 달력 화면을 연다
- **THEN** [이번 달 내보내기]는 보이지 않는다

#### Scenario: 선택지
- **WHEN** [이번 달 내보내기]를 누른다
- **THEN** "달력 이미지 보내기"와 "캘린더 파일 보내기"가 있는 바텀시트가 열리고 공유 창에서 보낼 곳을 고른다는 안내가 보인다

#### Scenario: 캘린더 파일 안내
- **WHEN** 바텀시트의 "캘린더 파일 보내기" 선택지를 본다
- **THEN** "공유 창에는 캘린더 앱이 없을 수 있어요."와 "나와의 채팅, 드라이브 등으로 보낸 뒤 받은 파일을 열면 캘린더 앱에 추가할 수 있어요."가 두 줄로 보인다

#### Scenario: 닫기
- **WHEN** 바텀시트에서 뒤로가기를 누른다
- **THEN** 바텀시트만 닫히고 달력 화면에 머무르며 아무것도 보내지 않는다

### Requirement: 캘린더 알림 안내 줄
내보내기 바텀시트에서 "캘린더 파일 보내기"를 고르면 공유 창을 열기 전에 확인 창을 SHALL 띄우고, 확인 창에 현재 알림 설정과 캘린더 앱 기본 알림의 차이를 시트 설명보다 큰 글자로 SHALL 보여 준다. 확인 창의 [보내기]를 눌러야 파일을 보내며, [취소]·뒤로가기는 파일을 보내지 않고 닫는다. 바텀시트에는 "캘린더 파일 보내기" 안내 두 줄만 남긴다. 켜져 있으면 "근무 전날 HH:00 알림을 파일에 넣어요. 비번·휴무는 제외해요.", 꺼져 있으면 "턴캘 알림을 파일에 넣지 않아요. 설정에서 켤 수 있어요."이다. 두 상태 모두 "캘린더 앱의 기본 알림이 따로 붙을 수 있어요."와 "이미 가져온 달은 그 달 일정을 지운 뒤 가져와야 바뀌어요. 저장된 캘린더는 가져온 뒤 확인해 주세요."를 SHALL 함께 표시한다. 문구는 좁은 화면에서 자연스럽게 줄바꿈하며, 실제 알림이 반드시 울리거나 전혀 울리지 않는다고 보장해서는 MUST NOT 된다.

#### Scenario: 알림 설정 안내
- **WHEN** 캘린더 알림이 기본값인 상태로 바텀시트에서 "캘린더 파일 보내기"를 고른다
- **THEN** 확인 창에 "근무 전날 21:00 알림을 파일에 넣어요. 비번·휴무는 제외해요."와 기본 알림 주의 문구가 보이고, 토글을 끈 뒤에는 "턴캘 알림을 파일에 넣지 않아요. 설정에서 켤 수 있어요."와 같은 주의 문구가 보인다. 두 상태 모두 다시 가져오기·저장 캘린더 안내가 보인다

#### Scenario: 시각 변경과 좁은 화면
- **WHEN** 전날 20:00을 선택한 뒤 360px 폭에서 "캘린더 파일 보내기"를 고른다
- **THEN** 확인 창에서 20:00 안내와 기본 알림 주의 문구를 모두 읽을 수 있고, 가로 스크롤·텍스트 잘림이 없으며 글자는 시트 설명(13px)보다 크다

#### Scenario: 확인 창 취소
- **WHEN** 확인 창에서 [취소]를 누른다
- **THEN** 확인 창이 닫히고 파일 공유 창은 열리지 않는다

### Requirement: 내보내는 내용
내보내기는 달력 화면에서 **보고 있는 달**의 1일부터 말일까지를 SHALL 대상으로 한다. 각 날짜의 근무는 달력 칸과 같은 규칙(그날 적용되던 패턴, 세부 내용 분류로 바뀐 근무 우선)으로 정하고, 근무 유형 이름·약어·색 사용자 정의를 반영한다. 날짜 세부 내용의 이름·시간·내용은 포함해서는 MUST NOT 된다. 패턴이 없는 날은 근무 없이 처리한다.

#### Scenario: 보고 있는 달
- **WHEN** 오늘이 10월이고 달력을 11월로 넘긴 뒤 내보낸다
- **THEN** 11월 1일~30일 근무가 담긴다

#### Scenario: 바뀐 근무와 사용자 정의
- **WHEN** 야간인 날에 분류 "휴무" 세부 내용이 있고 오후 이름을 "저녁"으로 바꿔 둔 상태에서 내보낸다
- **THEN** 그날은 휴무로, 오후인 날은 "저녁"으로 담긴다

#### Scenario: 세부 내용 제외
- **WHEN** 세부 내용 "병원 14:00 진료 예약"이 있는 달을 내보낸다
- **THEN** 이미지와 파일 어디에도 "병원"·시간·내용이 들어가지 않는다

### Requirement: 달력 이미지 보내기
"달력 이미지 보내기"는 보고 있는 달의 달력을 PNG 한 장으로 SHALL 그려 `turncal-YYYY-MM-<보낸 시각>.png` 이름, `image/png` 형식으로 기기의 파일 공유 창에 넘긴다. 이미지는 근무표 이름과 연·월 제목, 주 시작 요일 설정을 따른 요일 줄, 날짜별 숫자와 근무 약어(근무 색 배경), 그달에 쓰인 근무 유형의 약어·이름 범례, 앱 이름 "턴캘 교대근무 달력"을 포함한다. 근무는 색과 약어로 함께 구별되어야 하며(MUST), 이미지는 라이트 배경이다.

#### Scenario: 이미지 보내기
- **WHEN** 2026년 10월을 보며 "달력 이미지 보내기"를 고른다
- **THEN** `turncal-2026-10-`으로 시작하고 보낸 시각이 붙은 `.png` 파일이 `image/png`로 공유 창에 넘겨진다

#### Scenario: 이미지 내용
- **WHEN** 근무표 이름 "병동 3교대", 월요일 시작으로 보낸 이미지를 연다
- **THEN** 제목 "병동 3교대 · 2026년 10월", 월요일부터 시작하는 요일 줄, 날짜마다 근무 약어와 색, 범례, 앱 이름이 보인다

### Requirement: 캘린더 파일 보내기
"캘린더 파일 보내기"는 보고 있는 달의 근무가 있는 날마다 하루 종일 일정 하나를 담은 iCalendar(RFC 5545) 파일을 `turncal-YYYY-MM-<보낸 시각>.ics` 이름, `text/calendar` 형식으로 SHALL 기기의 파일 공유 창에 넘긴다. 일정 제목은 근무 유형 이름이고, 같은 날짜는 내보낼 때마다 같은 고유 ID를 가진다. 일정 설명에는 턴캘을 여는 토스 공유 링크를 넣되, 링크 만들기에 실패하면 링크 없이 보낸다. 공유 링크의 경로는 `intoss://` 스킴이어야 하며 `intoss-private://`를 써서는 MUST NOT 된다. 캘린더 알림이 켜져 있으면(기본값) 알림 대상 근무(주간·오후·야간·당직) 일정마다 일정 날짜 전날의 설정 시각에 울리는 표시 알림 하나를 SHALL 넣고, 알림 문구는 "내일 {근무 이름}"이다. 비번·휴무 일정과 알림이 꺼져 있을 때는 알림을 넣어서는 MUST NOT 된다. 같은 고유 ID는 파일의 식별 규칙이며, 캘린더 앱에서 기존 일정이 갱신되거나 중복을 막는다고 보장해서는 MUST NOT 된다. 파일에 알림이 없다는 것은 외부 캘린더 앱이 기본 알림을 추가하지 않는다는 뜻이 아니다.

#### Scenario: 파일 보내기
- **WHEN** 2026년 10월(근무가 31일 모두 있음)을 보며 "캘린더 파일 보내기"를 고른다
- **THEN** `turncal-2026-10-`으로 시작하고 보낸 시각이 붙은 `.ics` 파일이 공유 창에 넘겨지고, 파일에 하루 종일 일정 31개가 있으며 10월 13일 일정의 제목은 그날 근무 이름이다

#### Scenario: 근무 없는 날 제외
- **WHEN** 이력이 끝난 뒤 패턴이 없는 날이 섞인 달을 보낸다
- **THEN** 근무가 없는 날은 일정이 만들어지지 않는다

#### Scenario: 같은 고유 ID
- **WHEN** 같은 달을 두 번 보낸다
- **THEN** 두 파일의 같은 날짜 일정은 같은 고유 ID를 가진다

#### Scenario: 링크 실패
- **WHEN** 공유 링크 만들기가 실패한다
- **THEN** 링크 없는 파일이 공유 창에 넘겨진다

#### Scenario: 기본 알림
- **WHEN** 캘린더 알림이 기본값이고 10월 14일이 야간인 달을 보낸다
- **THEN** 10월 14일 일정에 10월 13일 21:00에 울리는 "내일 야간" 알림이 있다

#### Scenario: 비번·휴무 제외
- **WHEN** 10월 15일이 비번, 10월 16일이 휴무인 달을 보낸다
- **THEN** 두 날의 일정은 만들어지지만 알림은 없다

#### Scenario: 시각 변경
- **WHEN** 캘린더 알림을 "전날 19:00"으로 바꾼 뒤 보낸다
- **THEN** 알림 대상 일정의 알림이 모두 전날 19:00에 울리도록 들어간다

#### Scenario: 알림 끔
- **WHEN** 캘린더 알림 토글을 끈 뒤 보낸다
- **THEN** 파일의 어느 일정에도 알림이 없다

#### Scenario: 변경 뒤 재가져오기
- **WHEN** 같은 달의 근무와 알림 설정을 바꿔 다시 보낸 파일을 캘린더 앱으로 가져온다
- **THEN** 새 파일에는 바꾼 근무·알림이 담기되 앱이 기존 외부 일정을 직접 수정하지 않으며, 외부 앱의 갱신·중복 처리와 기본 알림 결과는 실제 사용 환경에서 확인한다

### Requirement: 저장 파일 이름
내보내는 파일 이름은 `turncal-YYYY-MM-YYYYMMDDHHMMSS.<확장자>` 형식으로 SHALL 만든다. 앞의 연·월은 보고 있는 달, 뒤의 숫자는 보낸 시각(기기 현지 시각, 초 단위)이다. 같은 이름의 파일이 기기에 이미 있으면 토스 앱이 저장을 거부하므로("파일이 이미 존재해요", 2026-10-21 실기기), 같은 달을 다시 보내도 이름이 겹치지 않아야 한다(MUST). 근무표 이름·호칭·근무 유형 이름 등 사용자가 입력한 값을 파일 이름에 넣어서는 MUST NOT 되며, 저장 경로는 앱이 정하지 않고 토스 앱·OS 공유 창에서 사용자가 고른 곳에 맡긴다.

#### Scenario: 사용자 입력과 무관한 이름
- **WHEN** 근무표 이름이 "병동/3교대 ../"인 상태에서 2026-10-21 11:45:30에 2026년 10월을 내보낸다
- **THEN** 파일 이름은 `turncal-2026-10-20261021114530.png`(또는 `.ics`)이고 근무표 이름은 파일 이름에 들어가지 않는다

#### Scenario: 다시 보내기
- **WHEN** 같은 달을 한 번 보낸 뒤 다시 보낸다
- **THEN** 두 파일 이름이 서로 달라 두 번째도 공유 창이 열린다

### Requirement: 내보내기 결과 안내
파일 공유 창은 사용자가 취소해도 성공으로 끝나므로, 공유 창이 정상적으로 열린 뒤에는 "저장했어요"처럼 보내기·저장이 끝났다고 단정하는 안내를 보여 주어서는 MUST NOT 된다. 공유 창을 열지 못하면(오류) 보내지 못했다는 안내를 달력 화면에 SHALL 보여 주며 앱 데이터는 바뀌지 않는다. 토스 앱이 파일 공유를 지원하지 않는 버전이면 시도하지 않고 토스 앱을 업데이트하면 쓸 수 있다고 MUST 안내한다.

#### Scenario: 공유 창을 연 뒤
- **WHEN** 공유 창이 열린 뒤 사용자가 보내거나 취소한다
- **THEN** 달력 화면에는 완료를 단정하는 안내가 나타나지 않는다

#### Scenario: 실패
- **WHEN** 공유 창을 여는 호출이 오류로 끝난다
- **THEN** 보내지 못했다는 안내가 보이고 설정·세부 내용 저장값은 그대로이다

#### Scenario: 지원하지 않는 버전
- **WHEN** 파일 공유를 지원하지 않는 토스 앱에서 내보내기 선택지를 누른다
- **THEN** 시도하지 않고 업데이트 안내가 보인다

### Requirement: 내보내기 뒤 리뷰 요청 창
이번 달 내보내기의 결과가 공유 창 열림이면 "턴캘이 도움이 됐나요?" 리뷰 요청 창을 SHALL 띄운다. 설명은 "리뷰를 남겨 주시면 턴캘을 더 좋게 만드는 데 큰 힘이 돼요."이고 버튼은 [다음에]·[리뷰 남기기]이다. 공유 창은 취소해도 열림으로 끝나므로 이 창은 내보내기 완료를 뜻하지 않으며, 완료 문구를 넣어서는 MUST NOT 된다. [리뷰 남기기]를 누를 때만 앱인토스 `requestReview`를 호출한다. [다음에]·뒤로가기는 요청하지 않고 닫는다. 어느 쪽으로 닫든 같은 실행 중에는 다시 띄우지 않는다. `requestReview`가 지원되지 않거나 실패·미지원 내보내기 뒤에는 띄우지 않는다. 리뷰 창 노출이나 작성 여부에 따라 다른 기능·보상을 바꿔서는 MUST NOT 된다.

#### Scenario: 내보내기 뒤 리뷰 요청 창
- **WHEN** 캘린더 파일 또는 달력 이미지를 보내 공유 창이 열렸다가 돌아온다
- **THEN** 리뷰 요청 창이 뜨고, 버튼을 누르기 전에는 `requestReview`를 호출하지 않는다

#### Scenario: 리뷰 남기기
- **WHEN** [리뷰 남기기]를 누른다
- **THEN** `requestReview`를 한 번 호출하고 창이 닫히며, 같은 실행에서 다시 내보내도 창이 다시 뜨지 않는다

#### Scenario: 다음에
- **WHEN** [다음에]를 누른다
- **THEN** `requestReview`를 호출하지 않고 창이 닫히며, 같은 실행에서 다시 내보내도 창이 다시 뜨지 않는다

#### Scenario: 실패 뒤
- **WHEN** 내보내기가 실패하거나 미지원이다
- **THEN** 리뷰 요청 창은 뜨지 않는다
