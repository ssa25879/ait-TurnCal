# Spec Delta

## MODIFIED Requirements

### Requirement: 캘린더 알림 안내 줄
내보내기 바텀시트는 "캘린더 파일 보내기" 안내 두 줄 아래에 현재 알림 설정과 캘린더 앱 기본 알림의 차이를 SHALL 보여 준다. 켜져 있으면 "근무 전날 HH:00 알림을 파일에 넣어요. 비번·휴무는 제외해요.", 꺼져 있으면 "턴캘 알림을 파일에 넣지 않아요. 설정에서 켤 수 있어요."이다. 두 상태 모두 "캘린더 앱의 기본 알림이 따로 붙을 수 있어요."와 "이미 가져온 달은 그 달 일정을 지운 뒤 가져와야 바뀌어요. 저장된 캘린더는 가져온 뒤 확인해 주세요."를 SHALL 함께 표시한다. 문구는 좁은 화면에서 자연스럽게 줄바꿈하며, 실제 알림이 반드시 울리거나 전혀 울리지 않는다고 보장해서는 MUST NOT 된다.

#### Scenario: 알림 설정 안내
- **WHEN** 캘린더 알림이 기본값인 상태로 바텀시트를 연다
- **THEN** "근무 전날 21:00 알림을 파일에 넣어요. 비번·휴무는 제외해요."와 기본 알림 주의 문구가 보이고, 토글을 끈 뒤에는 "턴캘 알림을 파일에 넣지 않아요. 설정에서 켤 수 있어요."와 같은 주의 문구가 보인다. 두 상태 모두 다시 가져오기·저장 캘린더 안내가 보인다

#### Scenario: 시각 변경과 좁은 화면
- **WHEN** 전날 20:00을 선택한 뒤 360px 폭에서 내보내기 시트를 연다
- **THEN** 20:00 안내와 기본 알림 주의 문구를 모두 읽을 수 있고, 가로 스크롤·텍스트 잘림이 없으며 실제 CSS 글자는 11px 미만으로 줄어들지 않는다

### Requirement: 캘린더 파일 보내기
"캘린더 파일 보내기"는 보고 있는 달의 근무가 있는 날마다 하루 종일 일정 하나를 담은 iCalendar(RFC 5545) 파일을 `turncal-YYYY-MM-<보낸 시각>.ics` 이름, `text/calendar` 형식으로 SHALL 기기의 파일 공유 창에 넘긴다. 일정 제목은 근무 유형 이름이고, 같은 날짜는 내보낼 때마다 같은 고유 ID를 가진다. 일정 설명에는 턴캘을 여는 토스 공유 링크를 넣되, 링크 만들기에 실패하면 링크 없이 보낸다. 공유 링크의 경로는 `intoss://` 스킴이어야 하며 `intoss-private://`를 써서는 MUST NOT 된다. 캘린더 알림이 켜져 있으면(기본값) 알림 대상 근무(주간·오후·야간·당직) 일정마다 일정 날짜 전날의 설정 시각에 울리는 표시 알림 하나를 SHALL 넣고, 알림 문구는 "내일 {근무 이름}"이다. 비번·휴무 일정과 알림이 꺼져 있을 때는 알림을 넣어서는 MUST NOT 된다. 같은 고유 ID는 파일의 식별 규칙이며, 캘린더 앱에서 기존 일정이 갱신되거나 중복을 막는다고 보장해서는 MUST NOT 된다. 파일에 알림이 없다는 것은 외부 캘린더 앱이 기본 알림을 추가하지 않는다는 뜻이 아니다.

#### Scenario: 파일 보내기
- **WHEN** 2026년 10월(근무가 31일 모두 있음)을 보며 "캘린더 파일 보내기"를 고른다
- **THEN** `turncal-2026-10-`으로 시작하고 보낸 시각이 붙은 `.ics` 파일이 공유 창에 넘겨지고, 파일에 하루 종일 일정 31개가 있으며 10월 13일 일정의 제목은 그날 근무 이름이다

#### Scenario: 근무 없는 날 제외
- **WHEN** 이력이 끝난 뒤 패턴이 없는 날이 섞인 달을 보낸다
- **THEN** 근무가 없는 날은 일정이 만들어지지 않는다

#### Scenario: 같은 고유 ID
- **WHEN** 같은 달을 두 번 보낸다
- **THEN** 두 파일의 같은 날짜 일정은 같은 고유 ID를 가진다

#### Scenario: 링크 실패
- **WHEN** 공유 링크 만들기가 실패한다
- **THEN** 링크 없는 파일이 공유 창에 넘겨진다

#### Scenario: 기본 알림
- **WHEN** 캘린더 알림이 기본값이고 10월 14일이 야간인 달을 보낸다
- **THEN** 10월 14일 일정에 10월 13일 21:00에 울리는 "내일 야간" 알림이 있다

#### Scenario: 비번·휴무 제외
- **WHEN** 10월 15일이 비번, 10월 16일이 휴무인 달을 보낸다
- **THEN** 두 날의 일정은 만들어지지만 알림은 없다

#### Scenario: 시각 변경
- **WHEN** 캘린더 알림을 "전날 19:00"으로 바꾼 뒤 보낸다
- **THEN** 알림 대상 일정의 알림이 모두 전날 19:00에 울리도록 들어간다

#### Scenario: 알림 끔
- **WHEN** 캘린더 알림 토글을 끈 뒤 보낸다
- **THEN** 파일의 어느 일정에도 알림이 없다

#### Scenario: 변경 뒤 재가져오기
- **WHEN** 같은 달의 근무와 알림 설정을 바꿔 다시 보낸 파일을 캘린더 앱으로 가져온다
- **THEN** 새 파일에는 바꾼 근무·알림이 담기되 앱이 기존 외부 일정을 직접 수정하지 않으며, 외부 앱의 갱신·중복 처리와 기본 알림 결과는 실제 사용 환경에서 확인한다
