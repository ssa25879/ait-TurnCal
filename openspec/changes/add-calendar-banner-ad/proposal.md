# Proposal

## Why

턴캘은 서버·로그인 없이 운영되는 무료 미니앱이라 수익 수단이 없다. 앱인토스 인앱 광고(토스 애즈) 배너를 사용자가 가장 자주 보는 달력 화면 맨 아래에 하나만 두어, 근무 확인 흐름을 방해하지 않으면서 노출 기반 수익을 얻는다. 위치는 출시 가이드·토스 애즈 SSP 정책 검토 결과(달력 격자는 누르는 요소가 아니고, [설정] 버튼과 간격을 둔 별도 영역이라 오클릭 위험이 낮음)로 정했다.

## What Changes

- 달력 화면 맨 아래, 달력 격자와 [설정] 버튼보다 아래에 넉넉한 간격을 두고 토스 애즈 배너 1개를 표시한다(전체 화면 너비, 고정 높이 96px).
- 배너는 라이트 테마로 고정하고(기기 다크모드를 따라가지 않음), "Ad" 표기·디자인·이벤트 흐름을 바꾸지 않는다. 광고 영역을 임의로 새로고침하지 않는다.
- 광고 SDK는 앱 시작 시 한 번만 초기화하고, 배너는 달력 화면이 보일 때 부착하고 떠날 때 제거한다.
- 지원하지 않는 환경(토스 앱 5.241.0 미만 등), 초기화·렌더링 실패, 표시할 광고 없음일 때는 배너 영역을 숨겨 빈 공간을 남기지 않는다.
- 개발·테스트에서는 테스트 광고 ID만 쓰고, 실제 광고 그룹 ID는 빌드 설정으로 주입한다. 실제 ID가 없는 출시 빌드에서는 배너를 표시하지 않는다.
- 다른 화면(초기 안내, 근무 패턴, 설정 목록, 화면 설정, 오류 화면, 바텀시트·다이얼로그)에는 광고를 넣지 않는다. 전면·리워드 광고는 범위 밖이다.

## Capabilities

### New Capabilities
- `in-app-ads`: 인앱 광고 노출 정책 — 배너 위치(달력 하단 1개)·표시 조건·숨김 조건·테마·광고 ID 사용 규칙과 광고를 넣지 않는 화면.

### Modified Capabilities
- 없음 (달력의 근무 표시·월 이동 요구사항은 바뀌지 않는다. 배너는 `in-app-ads`가 소유한다)

## Impact

- **코드:** `CalendarScreen`(하단 배너 영역), 광고 SDK 초기화 지점(App 최상위), 배너 부착·제거 훅/컴포넌트 신규, 스타일(전체 폭 배너 영역 — `.app` 좌우 여백 바깥으로 확장).
- **플랫폼 API:** `@apps-in-toss/web-framework`의 `TossAds.initialize`·`attachBanner`(+`isSupported`). 별도 의존성 추가 없음.
- **설정:** 실제 광고 그룹 ID를 빌드 환경 변수로 주입(`.env` 파일은 커밋하지 않음).
- **콘솔·출시:** 콘솔에서 광고 그룹(배너) ID 발급 필요. 출시 가이드의 "인앱 광고" 절과 토스 애즈 SSP 정책이 검토 대상이 된다. 샌드박스는 광고를 지원하지 않아 실기기 확인은 콘솔 QR로 한다.
- **외부 시스템:** 광고 SDK가 광고 요청 네트워크를 사용한다(앱 자체 네트워크 호출은 여전히 없음).
