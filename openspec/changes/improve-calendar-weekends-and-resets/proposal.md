# Proposal

## Why

v1 후보(`20261013-3`)를 실기기에서 써 본 결과 두 가지 사용성 문제가 확인됐다. 달력에서 주말·공휴일이 구분되지 않아 근무일과 쉬는 날을 함께 판단하기 어렵고, 초기화가 별도 "초기화" 화면에 모여 있어 근무 패턴·화면 설정을 되돌리려는 사용자가 찾기 어렵다. 출시 전에 바로잡는다.

## What Changes

- **주말 표시:** 달력 날짜 숫자를 요일에 따라 구분해 표시한다(일요일, 토요일). 요일 머리글과 같은 규칙을 날짜 칸에도 적용한다.
- **공휴일 표시:** 대한민국 공휴일(대체공휴일 포함)을 일요일과 같은 방식으로 표시하고, 날짜 화면에 공휴일 이름을 보여 준다. 공휴일은 근무 계산에 영향을 주지 않는다(표시 전용 — 기획서의 "공휴일에 따른 자동 근무 변경 제외"는 유지).
- **초기화 위치 변경:** "근무 패턴 초기화"는 근무 패턴 설정 화면 아래에, "화면 설정 초기화"는 화면 설정 화면 아래에 둔다. 각 동작·확인 절차·결과는 지금과 같다.
- **전체 초기화:** 현재 상태(설정 목록의 "초기화" 화면) 그대로 유지한다. 그 화면에는 전체 초기화만 남긴다(확정 필요 — 아래 Impact 참고).

## Capabilities

### New Capabilities
- `calendar-holidays`: 주말·공휴일 표시 규칙과 공휴일 데이터(범위·출처·갱신 방식).

### Modified Capabilities
- `shift-calendar`: "근무 유형 표시" 또는 별도 요구사항으로 날짜 숫자의 주말·공휴일 구분 표시.
- `settings-reset`: 근무 패턴·화면 설정 초기화의 위치가 각 설정 화면으로 이동, "초기화 화면"의 구성 변경.
- `display-settings`: 설정 목록의 "초기화" 항목 설명(요약 문구) 변경, 화면 설정 화면에 초기화 버튼 추가.
- `day-entries`: 날짜 화면에 공휴일 이름 표시.

> 이 change의 delta는 `add-day-entries-and-names`·`add-calendar-banner-ad`를 아카이브해 `settings-reset`·`day-entries` 등이 정식 명세에 생긴 뒤 작성한다.

## Impact

- **화면:** `Calendar`(날짜 숫자 색), `DayScreen`(공휴일 이름), `SettingsScreen`(근무 패턴 초기화 버튼 — 저장된 패턴이 있을 때만), `DisplaySettingsScreen`(화면 설정 초기화 버튼), `ResetScreen`(전체 초기화만), `SettingsMenu`(요약 문구).
- **도메인:** `src/domain/holidays.ts`(공휴일 표, 날짜 → 이름 조회) 신규. 네트워크·서버 없이 앱 안의 표로 판정한다.
- **확정이 필요한 결정(다음 세션 첫 단계):**
  1. 공휴일 데이터 범위(예: 2026~2030년)와 출처(정부 발표 월력요항 등), 이후 연도·임시공휴일 갱신 방식(앱 업데이트로 표 갱신).
  2. 토요일 색: 지금처럼 테마 강조색을 쓸지, 고정 색을 쓸지(토스 블루 계열 금지).
  3. 초기화 화면에 전체 초기화만 남길지, 세 가지를 모두 유지할지.
  4. 공휴일을 달력 칸에도 이름(축약)으로 보일지, 날짜 숫자 색 + 날짜 화면 이름으로 충분할지.
- **테스트:** `scripts/e2e/day-entries.mjs`의 초기화 경로 선택자를 새 위치에 맞게 고친다.
