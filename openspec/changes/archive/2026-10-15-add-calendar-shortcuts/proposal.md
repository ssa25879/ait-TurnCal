# Proposal

## Why

근무 패턴이나 이름을 고치려면 달력 → 설정 → 설정 목록 → 해당 항목으로 두 단계를 거쳐야 한다. 근무 패턴은 자주 고치는 값이라(실기기 확인 후 사용자 요청, 2026-10-14) 달력에서 바로 열 수 있어야 하고, 그 경로로 열었을 때 뒤로가기는 지나온 길인 달력으로 돌아가야 한다.

## What Changes

- 달력 화면 아래쪽([설정] 버튼 바로 위)에 **[근무 패턴 수정]**과 **[이름 수정]** 바로가기 버튼을 둔다. 누르면 설정 목록을 거치지 않고 각각 근무 패턴 설정 화면, 이름 화면이 바로 열린다.
- 근무 패턴이 없는 달력(패턴 초기화 뒤)에서는 안내 카드의 [근무 패턴 등록하기]가 같은 역할을 하므로 [근무 패턴 수정]은 보이지 않고 [이름 수정]만 보인다.
- 바로가기로 연 화면은 **뒤로가기가 달력으로 돌아온다**(설정 목록이 아님). 저장하지 않은 변경이 있으면 폐기 확인을 먼저 하고, 폐기하면 달력으로 돌아간다. 이름을 저장하면 달력으로 돌아가 바뀐 이름이 바로 보인다(패턴 저장은 지금도 달력으로 돌아간다).
- **첫 실행·전체 초기화 뒤에도 빈 달력**(실기기 확인 후 추가 요청, 2026-10-15; 사용자 결정: "첫 실행도 빈 달력"): 저장된 설정이 없으면 별도 등록 안내 화면 없이 근무가 비어 있는 달력으로 시작한다("근무 패턴이 없어요" 카드로 등록 유도). 전체 초기화 뒤에도, 앱을 다시 열어도 같다. 빈 달력은 저장하지 않은 기본 설정으로만 표시되고 뒤로가기는 종료다. 초기 등록 안내 화면(`SetupIntro`)은 없앤다. **BREAKING**: 첫 실행 화면과 뒤로가기 동작이 바뀐다.
- 기존 [설정] 버튼과 설정 목록 경로는 그대로이며 그 경로의 뒤로가기 계층(상세 → 설정 목록 → 달력)도 바뀌지 않는다.
- 저장 형식·이력 규칙·광고·화면 설정은 바꾸지 않는다. 화면 설정·초기화 바로가기는 이번 범위가 아니다.

### Modified Capabilities
- `shift-calendar`: 달력의 근무 패턴·이름 수정 바로가기 요구사항 추가
- `miniapp-shell`: 바로가기로 연 화면의 뒤로가기(달력 복귀·폐기 확인) 추가, 최초 화면은 항상 달력(수정)
- `schedule-names`: 바로가기로 연 이름 화면의 저장 후 이동 요구사항 추가
- `settings-reset`: 전체 초기화 뒤 빈 달력(수정)
- `shift-pattern-settings`: 초기 설정 안내를 빈 달력 카드로(수정)
- `settings-persistence`: 저장값 없을 때 빈 달력(수정)
- `in-app-ads`: 광고 없는 화면에서 초기 안내 제거(수정)

## Impact

- 코드: `src/App.tsx`(`names` 뷰에 달력 출처 표시, 뒤로가기·폐기 확인·저장 후 이동 분기, 전체 초기화 뒤 메모리 기본 설정), `src/platform/useBackHandler.ts`(등록 안내 화면의 뒤로가기), `src/components/CalendarScreen.tsx`(바로가기 버튼과 콜백), `src/style.css`.
- 테스트: 새 E2E 시나리오(바로가기 → 화면 열림, 뒤로가기·폐기 확인·저장 후 달력 복귀, 설정 목록 경로 불변, 패턴 없음 달력, 360px), 기존 E2E는 변경 없이 통과해야 한다. 뒤로가기 결정 함수(`decideBackAction`)는 등록 안내 화면에서 설정이 있으면 달력으로 가는 한 줄만 추가된다.
- 호환성: 저장 데이터·`version` 변경 없음.
- 출시 가이드: 새 오버레이·외부 이동·권한 없음. 최초 화면(달력)의 뒤로가기 종료 규칙 유지.
