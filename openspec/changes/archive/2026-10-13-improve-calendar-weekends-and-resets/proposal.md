# Proposal

## Why

v1 후보(`20261013-3`)를 실기기에서 써 본 결과 두 가지 사용성 문제가 확인됐다. 달력에서 주말·공휴일이 구분되지 않아 근무일과 쉬는 날을 함께 판단하기 어렵고, 초기화가 별도 "초기화" 화면에 모여 있어 근무 패턴·화면 설정을 되돌리려는 사용자가 찾기 어렵다. 출시 전에 바로잡는다.

## What Changes

- **주말 표시:** 달력 날짜 숫자를 요일 머리글과 같은 규칙으로 표시한다(일요일 빨강 계열, 토요일 테마 강조색).
- **공휴일 표시:** 2026~2035년 대한민국 관공서 공휴일(대체공휴일·임기만료 선거일 포함)을 앱 안의 자료로 판정해, 날짜 숫자를 일요일 색으로 바꾸고 달력 칸에 축약 이름(최대 3자), 날짜 화면에 전체 이름을 보여 준다. 공휴일은 근무 계산에 영향을 주지 않는다(표시 전용 — 기획서의 "공휴일에 따른 자동 근무 변경 제외"는 유지).
- **초기화 위치 변경:** "근무 패턴 초기화"는 근무 패턴 설정 화면 아래(저장된 패턴이 있을 때만), "화면 설정 초기화"는 화면 설정 화면 아래에 둔다. 동작·확인 절차·결과는 지금과 같다.
- **전체 초기화:** 설정 목록의 "초기화" 화면에 그대로 두고, 그 화면에는 전체 초기화만 남긴다.

## Capabilities

### New Capabilities
- `calendar-holidays`: 주말·공휴일 표시 규칙(달력 칸·날짜 화면·접근성 이름)과 공휴일 데이터 범위.

### Modified Capabilities
- `settings-reset`: 근무 패턴·화면 설정 초기화가 각 설정 화면으로 이동, 초기화 화면은 전체 초기화만, 확인 절차를 공통 요구사항으로 분리.
- `display-settings`: 설정 목록 시나리오(근무 패턴·화면 설정 화면의 초기화 버튼, 초기화 화면 구성) 갱신.

## Impact

- **화면:** `Calendar`(날짜 숫자 색, 공휴일 이름 줄), `DayScreen`(공휴일 이름), `SettingsScreen`(근무 패턴 초기화 — 저장된 패턴이 있을 때만), `DisplaySettingsScreen`(화면 설정 초기화), `ResetScreen`(전체 초기화만), `SettingsMenu`(요약 문구).
- **도메인:** `src/domain/holidays.ts` 신규(음력 공휴일 표 + 「관공서의 공휴일에 관한 규정」 대체공휴일 규칙 + 선거일 표). 네트워크·서버 없음.
- **확정된 결정(2026-10-13 사용자):** 범위 2026~2035(용량 확인 후 이후 연도 추가 검토), 토요일은 테마 강조색, 초기화 화면은 전체 초기화만, 공휴일은 달력 칸에도 축약 이름.
- **테스트:** `scripts/e2e/day-entries.mjs`의 초기화 경로를 새 위치로 고치고 주말·공휴일 표시 검사를 추가한다.
