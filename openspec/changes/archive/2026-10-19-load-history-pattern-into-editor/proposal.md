# Proposal

## Why

예전 근무제로 돌아가거나 패턴 초기화 뒤 다시 등록할 때, 사용자는 이력 목록에 보이는 근무 순서를 편집기에 한 칸씩 다시 입력해야 한다. 2026-10-14 실기기 확인에서 "이력을 누르면 그 패턴으로 바뀌는" 퀵스왑 요청이 있었으나, 바로 저장하면 위상(오늘 위치)이 어긋나고 적용 범위·이력 생성 흐름과 겹쳐 v1.1에서는 보류했다. 그때 정한 저위험 변형안(누르면 편집기에 **불러오기만** 한다)을 v1.2 첫 작업으로 진행한다.

## What Changes

- 근무 패턴 설정 화면의 패턴 이력 목록에서 **이전 패턴 항목**을 누르면 그 근무 순서가 편집기(draft)에 들어간다. 저장은 하지 않는다.
- 불러오면 **오늘 위치는 비운다.** 사용자가 오늘 칸을 고르기 전에는 [저장]이 막혀 있어 위상이 어긋난 채 저장되지 않는다.
- 저장하지 않은 편집 내용이 있으면 기존 확인 창(`ConfirmDialog`)으로 덮어쓸지 묻는다. 편집 내용이 없으면 바로 불러온다. 확인 창은 뒤로가기로 닫힌다(오버레이 우선 닫기 규칙).
- 확정은 기존 [저장]·적용 범위(오늘부터/전체 기간) 흐름을 그대로 쓴다. 저장 형식(`version: 3`)·이력 갱신 규칙은 바꾸지 않는다.
- **패턴 초기화 뒤**(현재 패턴 없음, 이력 있음)에도 이력 목록을 보여 주어 예전 패턴을 불러와 다시 등록할 수 있게 한다. 이력도 패턴도 없는 첫 등록에서는 지금처럼 목록을 숨긴다.
- 현재 패턴 행은 이미 편집기에 들어 있는 내용이라 누를 수 없는 표시용으로 둔다.
- pattern-history 명세의 "읽기 전용 목록"을 "수정·삭제는 없고, 이전 패턴은 누르면 편집기에 불러온다"로 바꾼다.

## Capabilities

### New Capabilities

(없음)

### Modified Capabilities

- `pattern-history`: "읽기 전용 패턴 이력 목록" 요구사항을 바꾼다 — 이전 패턴 항목을 누르면 편집기에 불러오고(오늘 위치 비움, 편집 중이면 확인), 초기화 뒤에도 이력이 있으면 목록을 표시한다. 수정·삭제 UI 금지와 색상만으로 구별 금지는 유지한다.

## Impact

- 코드: `src/components/PatternHistoryList.tsx`(이전 패턴 행을 버튼으로, `onLoad` 콜백), `src/components/SettingsScreen.tsx`(draft 교체·확인 창·스크롤), `src/domain/settingsDraft.ts`(불러오기용 draft 생성 함수), `src/App.tsx`(초기화 뒤에도 `timeline` 전달), `src/style.css`(행 버튼 스타일·터치 영역).
- 테스트: `settingsDraft` 단위 테스트, E2E `scripts/e2e/pattern-history.mjs`(읽기 전용 시나리오 → 불러오기 시나리오).
- 저장 형식·의존성·광고·내비게이션 계층 변경 없음. 번들 롤백 시에도 데이터 호환.
