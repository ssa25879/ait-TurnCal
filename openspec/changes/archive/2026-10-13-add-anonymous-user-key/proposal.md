# Proposal

## Why

앱인토스 비게임 출시 가이드의 "사용자 식별키 발급" 항목은 "사용자 식별자 값을 확인하여 저장하고, 미니앱이 정상적으로 시작돼요"를 요구한다. 턴캘은 로그인·서버 없이 기기 저장소만 쓰므로 지금은 식별키를 받지 않는다. 문서 본문(`getAnonymousKey`)은 선택 기능처럼 쓰여 있지만 체크리스트는 조건 없이 나열하므로, 검수 반려 위험을 없애기 위해 최소 구현을 넣는다(2026-10-13 사용자 결정).

## What Changes

- 앱 시작 시 앱인토스 SDK의 사용자 식별키 발급(비게임용)을 호출해 받은 식별키를 기기 로컬 저장소에 저장한다.
- 식별키 발급이 지원되지 않거나 실패해도 앱은 지금과 똑같이 시작·동작한다. 사용자에게 오류를 보이지 않는다.
- 식별키는 화면에 표시하지 않고 외부(서버)로 보내지 않는다. 설정·세부 내용 저장 방식은 바꾸지 않는다(기기 변경 시 데이터 이전은 범위 밖).
- 전체 초기화는 식별키 저장값도 지운다. 다음 실행 때 다시 받아 저장한다.

## Capabilities

### New Capabilities
- `user-identity`: 사용자 식별키 발급·저장 규칙(시작 시 발급, 실패 허용, 비노출·비전송).

### Modified Capabilities
- `settings-reset`: 전체 초기화가 지우는 범위에 식별키 저장값 포함, 재실행 시 식별키만 다시 저장됨을 명시.

## Impact

- **코드:** `src/storage/userKeyStorage.ts`(신규, `turncal.user` 키), `src/platform/useAnonymousKey.ts`(신규, 시작 시 1회 호출), `App.tsx`(훅 연결), `storage/reset.ts`(`resetAll`에 식별키 삭제 추가).
- **SDK:** `@apps-in-toss/web-framework` 3.7.0의 `User.getAnonymousKey`(토스 앱 5.232.0 이상). 샌드박스·Devtools mock은 가짜 값을 돌려주므로 실제 값은 실기기에서 확인한다.
- **출시:** 새 출시 후보 번들이 필요하다(`20261013-5`를 대체).
