# Proposal

## Why

출시 후보를 써 본 사용자 요청으로, 반복 패턴만으로는 표현할 수 없는 날(휴가·대체근무)과 일정(병원 예약 등)을 날짜에 직접 기록하고, 달력을 개인 근무표로 알아볼 수 있게 이름을 붙이며, 설정을 손쉽게 처음 상태로 되돌릴 수 있어야 한다. 원 기획서의 P1 "날짜별 예외 수정"을 이 요청과 합쳐 v1에 넣는다.

## What Changes

- **날짜 세부 내용:** 달력의 날짜 칸을 누르면 그 날짜 화면이 열리고, 세부 내용을 여러 개 작성·수정·삭제할 수 있다. 항목은 이름(필수), 시작~종료 시간(선택), 내용(선택), 분류(선택: 근무 유형 6종)로 구성된다.
- **그날 근무 변경:** 분류를 고른 항목이 있으면 그날 근무가 그 분류로 바뀐다(반복 패턴은 유지). 분류를 가진 항목이 여러 개면 기본은 가장 먼저 작성한 항목이고, 날짜 화면에서 다른 항목을 골라 바꿀 수 있다.
- **달력 표시:** 날짜 칸에 (바뀐 근무를 반영한) 근무 글자와, 세부 내용이 있으면 첫 항목 이름의 앞글자를 표시한다. 항목이 여러 개면 `+n`, 근무가 바뀐 날은 표시 점을 더한다. 날짜 칸은 누를 수 있는 요소가 된다.
- **이름:** 설정에서 사용자 호칭과 근무표 이름을 선택 입력하고, 달력 상단에 근무표 이름(기본 "내 근무표")과 호칭을 표시한다.
- **초기화:** 설정에 근무 패턴 초기화, 화면 설정 초기화, 전체 초기화를 추가한다. 각각 확인 후 실행되며 되돌릴 수 없음을 안내한다.
- **저장:** 설정 저장 형식을 `version: 3`(이름 추가, 패턴 초기화 상태 허용)으로 올리고 v1·v2를 마이그레이션한다. 세부 내용은 별도 키(`turncal.entries`)에 저장한다.

## Capabilities

### New Capabilities
- `day-entries`: 날짜 세부 내용의 작성·수정·삭제, 그날 근무 변경 규칙, 달력 칸 표시, 날짜 화면 흐름과 저장.
- `schedule-names`: 사용자 호칭·근무표 이름 입력과 달력 상단 표시.
- `settings-reset`: 근무 패턴·화면 설정·전체 초기화.

### Modified Capabilities
- `shift-calendar`: "근무 유형 표시"가 세부 내용으로 바뀐 근무와 표시 기호를 반영하고, 날짜 칸이 날짜 화면 진입점이 된다.
- `display-settings`: "설정 목록 화면"에 이름·초기화 항목이 추가된다.
- `settings-persistence`: 저장 형식 v3, 검증 범위, 상위 버전 기준(v4 이상), v2 → v3 마이그레이션.
- `miniapp-shell`: 설정 계층 뒤로가기에 이름·초기화 화면이 추가되고, 날짜·세부 내용 화면의 뒤로가기 규칙이 생긴다.

## Impact

- **화면:** `CalendarScreen`(상단 이름, 칸 탭), `Calendar`(칸 버튼화·표시 기호), 신규 날짜 화면·세부 내용 편집 화면·이름 화면·초기화 화면, `SettingsMenu` 항목 추가, `App` 화면 상태와 뒤로가기 규칙.
- **도메인:** 그날 근무 결정 규칙(패턴 + 세부 내용), 시간 검증·자정 넘김 표시, 세부 내용 정렬.
- **저장소:** `scheduleStorage`(v3, 마이그레이션), 신규 `entriesStorage`(`turncal.entries`), 초기화 시 키 삭제(`Storage.removeItem`).
- **배너 광고(`add-calendar-banner-ad`):** 날짜 칸이 누르는 요소가 되므로 배너와 달력 사이 간격 판단을 다시 확인한다(배너는 [설정] 버튼 아래라 배치는 그대로).
- **의존성:** 추가 없음(TDS 입력·시간 선택 컴포넌트 사용 여부는 design에서 결정).
