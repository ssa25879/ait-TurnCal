# Design

## Context

동기는 proposal.md 참고. 읽기 전용 감사(2026-10-15, `main` + `add-calendar-shortcuts` 기준)에서 확인한 사실:

- `style.css` 한 파일에 색상 변수만 있고(`--color-*`, `--shift-*`) 둥근 모서리는 6/8/10/12/14px, 글자 크기는 10~24px의 11단계가 값으로 직접 쓰인다.
- 10px 글자: `.cycle-item-order`(투명도 0.7), `.today-badge`. `.month-nav-button`은 40×40, `.time-clear`는 글자 13px + 위아래 4px 여백의 텍스트 버튼(높이 약 26px).
- `.calendar-cell`은 `min-height: 86px`이고 6줄이라 격자만 약 520px이다. 360×740에서 격자 끝이 첫 화면 밖으로 밀린다.
- `.calendar-cell.is-outside { opacity: 0.35 }`라 이번 달 밖 날짜의 근무 약어가 거의 보이지 않는다. `.calendar-holiday`는 11px 글자가 `--color-danger`(#f04452)로 흰 배경 대비 약 3.6:1이다.
- 선택 카드 스타일이 화면마다 다르다(`.theme-option` 2px 테두리 + 연한 배경, `.scope-option` 1px, `.category-option` 근무색 배경, `.today-cell` 테두리만). DayScreen의 "그날 근무로 적용"이 `.theme-option`·`.theme-name`·`.theme-check`를 빌려 쓴다.
- SettingsScreen·DisplaySettingsScreen은 [초기화](`ResetAction`)가 [저장]보다 위에 있다.
- E2E가 의존하는 값: 일요일 숫자 색 `rgb(240,68,82)`(`day-entries`), 오늘 칸 `borderTopColor`(`display-settings`), 오늘 카드 높이·배너 간격 32px(`today-summary`·`banner`), 20자 이름 360px 겹침 검사·버튼 높이 36px(`calendar-shortcuts`), `.theme-option`/`.scope-option`/`.category-option` 선택자.

## Goals / Non-Goals

**Goals:**
- 가이드 위반을 없앤다(11px 미만 0개, 터치 영역 44px 이상, 대비 개선).
- 360×740·390×844 모두에서 6주 격자가 스크롤 없이 모두 보이게 한다.
- 날짜·편집·설정 화면에서 주 동작이 위험 동작보다 먼저 보이고 선택 카드가 일관된다.
- 같은 값을 한 곳에서 관리하는 기준 변수를 만든다.

**Non-Goals:**
- 동작·상태·컴포넌트 API 변경, 저장 형식 변경.
- 오늘·내일 카드 형태·토요일 색·테마 추가(사용자 결정으로 제외).
- 하단 고정 CTA(safe-area·배너와의 겹침 위험이 있어 이번에는 하지 않음).

## Decisions

### 1. 기준 변수를 먼저 도입하고, 다음에 화면을 고친다
`:root`에 `--radius-s/m/l`(8/12/16), `--space-1..6`(4/8/12/16/20/24), `--font-xs/s/m/l/xl/xxl`(11/13/15/17/20/24)를 추가하고 기존 값을 가장 가까운 단계로 옮긴다. 이 단계는 화면이 거의 바뀌지 않는 기계적 리팩터링이라 단독 커밋·전후 스크린샷 비교로 검증한다. 이후 단계는 변수만 고치면 되게 한다.
- 이유: 값이 흩어져 있으면 P0·밀도 수정이 곳곳에서 누락된다. 리팩터링과 의도된 변경을 한 커밋에 섞지 않는다.
- 대안: 화면별로 값만 고침 — 같은 문제가 재발해 거부.

### 2. 달력 칸은 높이를 줄이고, 배지는 한 크기로 통일한다
`.calendar-cell`의 `min-height`를 86px에서 약 64~68px로 줄이고(정확한 값은 360×740에서 격자 끝이 안전 영역 위에 들어오는 최대값으로 정한다), 칸 안 줄 간격을 줄인다. 배지는 칸·오늘 카드·날짜 화면이 한 크기(28px)를 쓴다. 오늘 표시는 2px 테두리를 반드시 남기고 연한 배경을 더한다(E2E가 테두리를 검사).
- 이유: 사용자 결정 "첫 화면에 모두 보이도록". 세부 내용 앞글자 줄(`calendar-marker`)은 높이를 줄이되 11px 이상을 유지한다.
- 대안: 오늘·내일 카드를 줄여 공간 확보 — 카드 2장 유지가 사용자 결정이라 거부.

### 3. 이름 헤더는 한 줄 + 보조 글자
근무표 이름(17~20px, 진한 글자 색)과 호칭(13px 보조)을 같은 줄에 두고 월 제목은 20px로 낮춘다. 이름이 20자일 때도 360px에서 줄바꿈으로 겹치지 않아야 한다(`min-width: 0`·말줄임 또는 두 줄 허용).
- 이유: 머리글이 둘로 경쟁하는 문제와 세로 공간을 함께 해결한다.

### 4. 설정 화면은 "주 동작 → 보조 → 위험" 순서
SettingsScreen·DisplaySettingsScreen에서 [저장]을 [초기화] 영역보다 위로 올린다. 초기화는 구분선 아래 위험 영역으로 둔다(색은 기존 `danger` 변형 유지). 하단 고정 CTA는 하지 않는다.
- 이유: 저장하려고 끝까지 스크롤하는 문제를 없애면서 safe-area·배너와의 상호작용 위험을 피한다.

### 5. 선택 카드는 공용 클래스를 추가하고 기존 클래스는 남긴다
`.option-card`·`.is-selected`를 정의하고 `.theme-option`·`.scope-option`·`.category-option`은 같은 규칙을 공유하도록 selector 목록으로 묶는다(클래스 제거 없음). DayScreen의 "그날 근무로 적용"은 `.option-card`로 바꾸되 `.theme-*`를 더는 빌리지 않는다.
- 이유: E2E 선택자를 깨지 않고 스타일만 통일한다.

### 6. 검증은 스크린샷 + 자동 검사
각 단계마다 360×740·390×844에서 달력(패턴 있음·없음·20자 이름·공휴일 있는 달), 날짜 화면, 세부 내용 편집, 설정 목록·패턴·이름·화면 설정·초기화, 오류 화면을 3개 테마로 확인한다. 자동 검사: 11px 미만 글자 0개, 버튼·링크 터치 영역 44px 이상(아이콘 버튼 포함), 가로 스크롤 없음을 E2E에 추가한다.

## Risks / Trade-offs

- [칸 높이를 줄이면 세부 내용 앞글자·공휴일 이름이 답답해질 수 있음] → 줄 간격을 함께 조정하고 공휴일 짧은 이름 줄은 유지, 스크린샷으로 판단한다.
- [공용 스타일로 묶다가 한 화면의 미세 간격이 바뀜] → 기준 변수 도입 단계를 단독으로 두고 전후 스크린샷 차이를 의도 범위에서만 허용한다.
- [E2E의 높이·색 검사가 깨짐] → 오늘 칸 테두리·일요일 숫자 색·배너 간격 32px·오늘 카드 높이 44px 이상은 유지 값으로 두고, 바뀌는 값은 해당 E2E 줄을 함께 고친다.
- [`move-settings-to-navbar`와 하단 영역이 겹쳐 충돌] → 이 change는 [설정] 버튼의 존재 여부를 건드리지 않고 스타일만 바꾸며, 두 change는 순서대로(이 change 먼저) 진행한다.

## Migration Plan

- 저장 데이터 변경·마이그레이션 없음.
- 배포: 기능 브랜치 → 단위·시간대·E2E 통과 → 단계별 `build:adtest` 실기기 확인 → 다른 업데이트와 함께 실제 광고 ID 번들로 한 번에 출시(사용자 계획).
- 롤백: 콘솔에서 이전 번들로 되돌린다.
