# Design

## Context

동기는 proposal.md 참고. 현재 구조에서 영향이 있는 사실(2026-10-14 `main` 기준):

- `StoredSettingsV3.pattern`은 `WorkPattern | null`이고 `null`(패턴 초기화 후)은 이미 유효한 저장 상태다. `patternHistory`는 패턴이 없어도 유지된다.
- `App.tsx`는 `pattern !== null`을 기준으로 ① 시작 시 첫 화면(달력/등록 안내) ② 달력·날짜·설정 목록 렌더링 가드 ③ 뒤로가기의 `hasSavedSettings`를 정한다. 그래서 패턴이 없으면 설정 목록·이름·화면 설정에 갈 수 없고 설정 화면의 뒤로가기는 "최초 흐름(앱 종료)"이다.
- 근무 계산은 `resolvePattern(date, timeline)`(그날 패턴) → `getEffectiveShift(date, pattern, day)`(세부 내용 분류 반영) 순서이고, `PatternTimeline.current`는 항상 `WorkPattern`이다.
- 달력 칸·날짜 화면·오늘/내일 요약이 모두 이 두 함수를 쓰므로 판정 지점이 하나로 모여 있다.
- 패턴 초기화(`runResetPattern`)는 설정을 저장한 뒤 `setup-intro`로 이동한다.

## Goals / Non-Goals

**Goals:**
- 패턴 초기화 뒤에도 달력(과 이름·화면 설정 접근)을 쓸 수 있게 하고, 근무만 비어 보이게 한다.
- 이력이 남아 있으면 과거 날짜는 이력대로 표시한다.
- 저장 형식·이력 규칙·첫 실행 흐름을 바꾸지 않는다.

**Non-Goals:**
- 패턴 없음 상태에서 근무를 자동 추정하거나 마지막 패턴을 계속 이어 붙이는 동작.
- 이력 항목 편집·퀵스왑(별도 후보).
- 첫 실행(저장된 설정 없음)의 등록 안내 변경.

## Decisions

### 1. "패턴 없음"을 값으로 표현한다 (`null`)
`PatternTimeline.current`를 `WorkPattern | null`로 넓히고 `resolvePattern`이 `WorkPattern | null`을 돌려준다(패턴이 없고 날짜가 마지막 `until` 이상이면 null). `getEffectiveShift(date, pattern | null, day)`는 `{ shift: ShiftType | null, overridden }`을 돌려주고, 세부 내용 분류가 있으면 패턴 없음이어도 그 근무를 쓴다(`overridden: true`). `summary.ts`의 `DaySummary.shift`도 null을 허용한다.
- 이유: 판정 지점이 이미 하나라서 null 전파만 처리하면 달력·날짜 화면·요약이 자동으로 일치한다. "임시 빈 패턴" 같은 가짜 값을 만들지 않는다.
- 대안: ① 빈 `cycle`을 가진 가짜 `WorkPattern` — 길이 검증(1~56)·`getShift`의 0 길이 예외와 충돌해 거부. ② 패턴이 없으면 달력 대신 별도 "빈 화면" 컴포넌트 — 이력·세부 내용 표시와 날짜 화면 진입이 중복 구현이라 거부.

### 2. 화면 분기 기준을 `pattern`에서 `settings`로 바꾼다
시작 시 설정이 정상으로 읽히면 패턴 유무와 상관없이 달력으로 간다(없으면 지금처럼 등록 안내, 읽기 오류는 오류 화면). 달력·날짜·설정 목록 가드는 `settings` 존재 기준으로 하고, `useBackHandler`의 `hasSavedSettings`도 "저장된 설정 레코드가 있는가"로 바꾼다. 패턴 초기화·전체 초기화 이동은 각각 달력·등록 안내(전체 초기화는 설정이 사라지므로 기존대로)다.
- 이유: 뒤로가기 계층(설정 상세 → 설정 목록 → 달력)과 설정 접근이 패턴 유무와 무관하게 동일해진다. 첫 실행(레코드 없음)만 "최초 흐름(종료)"으로 남는다.

### 3. 빈 달력의 안내는 달력 상단 카드 하나로
패턴이 없을 때만 오늘·내일 요약 위(또는 대체)에 안내 카드 "근무 패턴이 없어요 · [근무 패턴 등록하기]"를 둔다. 버튼은 설정 목록을 거치지 않고 근무 패턴 설정(첫 등록) 화면으로 이동한다. 오늘·내일 요약 카드는 유지하되 패턴이 없는 날은 "근무 패턴 없음"을 표시한다.
- 이유: 등록 유도는 한 곳에 명확히 두고 달력의 나머지는 평소와 같게 유지한다. 바텀시트·전면 노출을 쓰지 않아 출시 가이드의 진입 시 바텀시트 금지와 충돌하지 않는다.
- 대안: 요약 카드 안에서 등록 유도 — 두 카드에 중복 노출돼 거부.

### 4. 설정 목록·편집 화면의 패턴 없음 처리
`SettingsMenu`는 `cycleLength`가 없을 때 근무 패턴 항목에 "등록되지 않음" 같은 보조 문구를 보여 준다. 근무 패턴 설정 화면은 `saved === null`이므로 이미 "첫 등록" 흐름(적용 범위 없음, 초기화 버튼 없음, 이력 목록 숨김)으로 동작하며, 저장 시 `App.savePattern`이 기존 이력을 유지한다(이미 구현됨).

## Risks / Trade-offs

- [`pattern` 가드가 여러 곳이라 누락 시 빈 화면·크래시] → 가드 변경 지점을 tasks에 나열하고 E2E로 패턴 초기화 → 달력·날짜 화면·설정 목록·뒤로가기를 모두 확인한다. 타입을 `| null`로 넓혀 컴파일러가 누락을 잡게 한다.
- [패턴 초기화 뒤 날짜 화면의 "근무 변경: A → B" 문구가 패턴 없음 처리에서 어색] → 패턴 없음이면 "패턴 근무" 비교 줄을 생략하고 세부 내용 분류 근무만 보여 준다(명세: "근무 패턴이 없어요").
- [사용자가 빈 달력을 오류로 오해] → 안내 카드가 항상 상단에 보이고 버튼 하나로 등록으로 이어진다.
- [롤백 시 이전 앱은 `pattern: null`을 등록 안내로 처리] → 저장 형식이 같아 데이터 손상 없음. 이전 동작과 같다.

## Migration Plan

- 저장 데이터 변경·마이그레이션 없음.
- 배포: 기능 브랜치 → 단위·시간대·E2E 통과 → `build:adtest`로 실기기 확인 → 다른 업데이트와 함께 실제 광고 ID 번들로 한 번에 출시(사용자 계획).
- 롤백: 콘솔에서 이전 번들로 되돌린다.
