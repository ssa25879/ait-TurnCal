# Proposal

## Why

근무 패턴을 초기화하면 지금은 곧바로 "근무 패턴 등록 안내" 화면으로 보내져서, 앱을 쓰던 사용자가 달력·이름·화면 설정에 접근할 수 없고 "패턴만 지우고 다시 설정"하는 흐름이 막힌 느낌을 준다(실기기 확인 피드백, 2026-10-14). 패턴 초기화는 패턴만 지우는 동작이므로, 초기화 뒤에도 달력은 그대로 보이되 근무 표시만 비어 있는 상태가 자연스럽다. 이력(패턴 변경 이력)이 남아 있으면 과거 날짜는 이력대로 계속 보여야 한다.

## What Changes

- 근무 패턴 초기화 뒤에 등록 안내 화면 대신 **근무가 비어 있는 달력**을 보여 준다. 달력 위쪽에 "근무 패턴이 없어요" 안내와 **[근무 패턴 등록하기]** 버튼을 둔다.
- 패턴이 없는 날짜는 근무 배지 없이 날짜만 표시한다. 패턴 이력이 있으면 마지막 이력 종료일 전의 날짜는 이력의 패턴대로 계속 표시한다. 날짜 세부 내용으로 근무를 바꿔 둔 날은 그 근무가 그대로 보인다.
- 오늘·내일 요약 카드와 날짜 화면은 패턴이 없으면 "근무 패턴 없음"을 보여 주고 나머지 기능(세부 내용 추가 등)은 그대로 쓸 수 있다.
- 설정이 저장돼 있으면 패턴이 없어도 **달력이 최초 화면**이다(뒤로가기는 앱 종료). 설정 목록·이름·화면 설정·초기화에 패턴 없이도 접근할 수 있고 뒤로가기 계층(설정 상세 → 설정 목록 → 달력)도 같다.
- 저장된 설정이 전혀 없는 **첫 실행**과 설정을 읽지 못한 오류 화면은 지금과 같다(등록 안내/오류 안내).
- 저장 형식은 바뀌지 않는다(`pattern: null`인 `version: 3` 설정은 이미 유효하다).

### Modified Capabilities
- `shift-calendar`: 패턴이 없는 달력(빈 칸, 등록 안내, 날짜 화면 문구) 요구사항 추가
- `today-summary`: 패턴이 없을 때의 요약 표시 요구사항 추가
- `pattern-history`: 패턴이 없는 날짜의 근무 판정(이력 종료일 이후는 없음) 요구사항 추가
- `miniapp-shell`: "최초 화면 뒤로가기 시 종료" — 설정이 있으면 패턴이 없어도 달력이 최초 화면
- `settings-reset`: "근무 패턴 초기화" — 초기화 뒤 빈 달력이 표시된다

## Impact

- 코드: `src/App.tsx`(초기 뷰·`pattern` 가드·초기화 뒤 이동·뒤로가기 `hasSavedSettings`), `src/domain/patternHistory.ts`(`current` 없음 허용, 패턴 없는 날짜), `src/domain/dayEntries.ts`(`getEffectiveShift`가 패턴 없음 허용), `src/domain/summary.ts`, `Calendar.tsx`·`CalendarScreen.tsx`·`DayScreen.tsx`·`TodaySummary.tsx`·`SettingsMenu.tsx`, `src/platform/useBackHandler.ts`, `src/style.css`.
- 테스트: 도메인 단위 테스트 추가·수정, 패턴 초기화 뒤 화면을 가정한 기존 E2E 갱신(`pattern-history`, `mvp-regression` 등), 새 E2E 시나리오.
- 호환성: 저장 데이터·`version` 변경 없음. 롤백해도 데이터 호환(이전 앱은 패턴 없음을 등록 안내로 처리).
- 출시 가이드: 새 오버레이·외부 이동·권한 없음. 최초 화면 종료 규칙(뒤로가기 시 종료)은 유지.
