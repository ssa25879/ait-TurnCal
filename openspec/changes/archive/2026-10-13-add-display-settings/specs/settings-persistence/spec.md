# Spec Delta

## MODIFIED Requirements

### Requirement: 설정 저장 형식
설정은 앱인토스 로컬 저장소의 단일 키 `turncal.settings`에 JSON 문자열로 SHALL 저장되며, `version`(현재 2), 패턴(기준일, 근무 유형 순서), 주 시작 요일, 테마 색을 포함한다.

#### Scenario: 저장 내용
- **WHEN** 기준일 `2026-10-13`, 패턴 `[주간, 야간, 비번, 휴무]`, 주 시작 요일 일요일, 테마 인디고로 저장한다
- **THEN** `turncal.settings`에 `version: 2`와 네 값이 모두 포함된 JSON 문자열이 저장된다

### Requirement: 저장 데이터 검증
복원 시 시스템은 version, 날짜 유효성, 근무 유형 값, 패턴 길이(1~56), 주 시작 요일 값, 테마 값(version 2 이상)을 SHALL 검증한다. 하나라도 유효하지 않으면 손상 데이터로 MUST 처리된다.

#### Scenario: 알 수 없는 근무 유형
- **WHEN** 저장된 패턴에 정의되지 않은 근무 유형 값이 있다
- **THEN** 손상 데이터로 처리된다

#### Scenario: JSON 파싱 실패
- **WHEN** 저장된 값이 JSON으로 해석되지 않는다
- **THEN** 손상 데이터로 처리된다

#### Scenario: 알 수 없는 테마
- **WHEN** `version: 2` 설정의 테마 값이 정의된 세 테마가 아니다
- **THEN** 손상 데이터로 처리된다

### Requirement: 손상·상위 버전 데이터 보존
손상 데이터나 현재 앱이 모르는 상위 version 데이터를 만나면 시스템은 앱을 중단하지 않고 오류를 SHALL 안내하며, 사용자가 명시적으로 다시 설정해 저장하기 전에는 기존 저장값을 삭제하거나 덮어써서는 MUST NOT 된다.

#### Scenario: 손상 데이터
- **WHEN** 손상된 설정이 저장된 상태로 앱을 연다
- **THEN** 오류 안내와 [다시 설정] 선택지가 표시되고 저장값은 그대로 남아 있다

#### Scenario: 상위 버전 데이터
- **WHEN** `version: 3` 이상의 설정이 저장된 상태로 이 버전의 앱을 연다
- **THEN** 손상 데이터와 같은 안내가 표시되고 저장값은 삭제되지 않는다

#### Scenario: 다시 설정 후 저장
- **WHEN** 사용자가 [다시 설정]을 선택해 새 설정을 [저장]한다
- **THEN** 그때 비로소 기존 저장값이 새 설정으로 덮어써진다

## ADDED Requirements

### Requirement: 이전 버전 설정 마이그레이션
`version: 1` 설정은 손상 데이터가 아니라 유효한 이전 버전으로 SHALL 복원되며, 테마는 기본값 인디고로 채워진다. 복원만으로는 저장값을 다시 쓰지 않고(MUST NOT), 사용자가 다음에 설정을 저장할 때 `version: 2`로 기록된다.

#### Scenario: v1 설정으로 실행
- **WHEN** MVP에서 저장한 `version: 1` 설정이 있는 상태로 새 버전 앱을 연다
- **THEN** 같은 패턴·기준일·주 시작 요일로 달력이 표시되고 테마는 인디고이며 저장값은 그대로 `version: 1`이다

#### Scenario: v1 이후 첫 저장
- **WHEN** v1 설정으로 실행한 뒤 테마를 딥 틸로 바꾼다
- **THEN** 저장값이 기존 패턴·주 시작 요일을 유지한 `version: 2` 설정으로 바뀌고 테마는 딥 틸이다
