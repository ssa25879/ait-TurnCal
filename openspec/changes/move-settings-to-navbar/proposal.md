# Proposal

## Why

달력 하단에 [근무 패턴 수정]·[이름 수정]·[설정] 버튼이 모두 쌓여 무겁고, 달력 첫 화면에 6주 격자를 모두 보이게 하려면 세로 공간을 줄여야 한다. 사용자 결정(2026-10-15): 설정 진입은 달력 하단 버튼이 아니라 **토스 내비게이션 바의 기능 버튼**으로 옮긴다. 출시 가이드는 미니앱 기능 버튼을 최대 1개까지 허용한다("선택 사항").

## What Changes

- 달력에서 설정 목록으로 들어가는 진입점을 하단 [설정] 버튼에서 **내비게이션 바 기능 버튼 1개**("설정")로 옮긴다. 하단 [설정] 버튼은 없앤다.
- 내비게이션 바 기능 버튼은 **달력 화면에서만** 보인다(다른 화면에서는 숨김). 누르면 설정 목록이 열리고 이후 뒤로가기 계층(설정 목록 → 달력)은 그대로이다.
- 기능 버튼을 지원하지 않거나 등록에 실패하는 환경에서는 설정에 들어갈 수 없게 되므로 **하단 [설정] 버튼을 대체 수단으로 보여 준다**(시스템 대체 경로).
- 하단에는 [근무 패턴 수정]·[이름 수정] 바로가기만 남고, 배너와의 간격 규칙(직전 요소 아래 32px 이상)은 그대로 적용된다.
- 저장 형식·바로가기·뒤로가기 규칙·오늘·내일 카드·토요일 색은 바뀌지 않는다.
- **BREAKING(조작 변화):** 기존 사용자는 하단 [설정] 대신 상단 바의 설정 버튼을 써야 한다.

## Impact

- 코드: `src/App.tsx`(기능 버튼 등록·해제, 클릭 이벤트 → 설정 목록 이동, 달력일 때만 노출), `src/components/CalendarScreen.tsx`(하단 [설정] 버튼을 조건부 대체 수단으로), 필요하면 `src/platform/`에 작은 훅(`useNavSettingsButton`).
- SDK: `partner.addAccessoryButton`·`tdsEvent.addEventListener('navigationAccessoryEvent', ...)`(`@apps-in-toss/web-framework`). Devtools mock이 액세서리 이벤트를 지원한다고 알려져 있으나 실제 호출 방식은 구현 때 확인한다.
- 테스트: 단위 테스트(훅의 등록·해제·대체 판단), E2E(mock에서 액세서리 클릭 → 설정 목록, 달력이 아닌 화면에서 숨김, 지원하지 않을 때 하단 버튼, 기존 [설정] 클릭 E2E 수정), `banner`·`today-summary`의 배너 간격 기준을 새 하단 요소로 수정.
- 출시 가이드: 기능 버튼은 최대 1개, 클릭 동작이 명확해야 한다. **실기기 확인 필요**: 아이콘·이름 표시, 더보기(⋯) 옆 위치, 라이트 모드에서 보이는지.
- 선행 조건: `add-calendar-shortcuts`가 아카이브·`main` 병합된 뒤 시작한다. 그 change가 추가한 `shift-calendar`의 "근무 패턴·이름 수정 바로가기" 요구사항 문장("[설정] 버튼 바로 위")은 병합 뒤 이 change에서 수정한다(tasks 1.1).
