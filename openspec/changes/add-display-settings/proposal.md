# Proposal

## Why

MVP에서는 달력 모양 설정(주 시작 요일)이 달력 화면 아래에 토글로 노출되어 있어 근무 확인 화면이 설정 UI와 섞인다. 실기기 확인 뒤 사용자 요청으로, 달력 모양을 바꾸는 설정은 설정 창에서 하도록 옮기고, 함께 계획한 테마 색 선택(인디고·딥 틸·코랄)을 같은 "화면 설정"으로 묶어 다음 디자인 작업에서 한 번에 진행한다.

## What Changes

- 주 시작 요일(일/월) 선택을 달력 화면에서 제거하고 설정 창으로 옮긴다. 변경은 기존처럼 즉시 저장되고 달력에 반영된다.
- 설정 창에서 앱 테마 색을 인디고(`#4F46E5`, 기본)·딥 틸(`#0F766E`)·코랄 오렌지(`#E8590C`) 중에서 고를 수 있다. 선택은 버튼·오늘 강조·선택 칸 등 앱의 강조색과 TDS 컴포넌트 색에 반영되고 재실행 후에도 유지된다.
- 설정 저장 형식에 테마 값을 추가한다(`version` 증가와 기존 v1 데이터 마이그레이션). v1 데이터는 기본 테마(인디고)로 복원된다.
- 다크모드는 범위에서 제외한다(비게임 출시 가이드의 라이트 모드 필수 항목). 앱 로고·콘솔 등록 대표색은 인디고로 유지한다.

## Capabilities

### New Capabilities
- `display-settings`: 설정 창의 화면 설정 — 테마 색 선택과 달력 모양(주 시작 요일) 설정의 위치·동작.

### Modified Capabilities
- `shift-calendar`: 주 시작 요일 설정 요구사항의 위치가 달력 화면에서 설정 창으로 바뀐다.
- `settings-persistence`: 저장 형식에 테마 값이 추가되고 v1 → 신규 version 마이그레이션 규칙이 생긴다.

> 위 두 capability는 `add-turncal-mvp`를 아카이브해 `openspec/specs/`에 반영한 뒤 delta로 작성한다.

## Impact

- **화면:** `CalendarScreen`(주 시작 요일 토글 제거), 설정 진입 구조(근무 패턴 설정과 화면 설정을 한 설정 창에 둘지, 설정 목록 화면을 둘지 — design 단계에서 결정), 뒤로가기 규칙(설정 화면 구성이 바뀌면 `miniapp-shell` 규칙 점검).
- **스타일:** `--color-primary` 등 강조색을 테마별 토큰으로 분리, `TDSMobileAITProvider`의 `brandPrimaryColor`를 선택된 테마로 전달.
- **저장소:** `scheduleStorage`의 스키마 버전 증가, 마이그레이션과 테스트.
- **브랜드:** 세 테마 색 모두 토스 블루 계열이 아님을 확인함. `apps-in-toss.config.ts`의 `brand.primaryColor`와 로고는 인디고로 유지.
