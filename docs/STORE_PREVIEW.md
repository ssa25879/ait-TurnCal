# 턴캘 미리보기·스크린샷 설계 (콘솔 앱 등록 2단계)

콘솔 "미리보기 및 스크린샷" 항목에 올릴 이미지의 구성·규격·촬영 방법을 정한다.

## 0. 현재 상태 (2026-10-13 밤)

- **이미지 5장 완성**: `assets/store/preview-1.png` ~ `preview-5.png`(전부 636×1048 PNG, 33~73KB). 내용 확인 완료.
- **콘솔 업로드는 아직 안 했다.** 콘솔 앱 등록 폼 2단계의 "미리보기 및 스크린샷"에 올릴 차례다(`find`로 `type="file"` 입력을 찾아 `file_upload`, 업로드 전 사용자 확인). 올린 뒤 "임시저장". 절차 메모는 `docs/NEXT_STEPS.md` 1-3.
- 시안은 2종을 만들었고 **A(흰 배경, 단색 테두리)로 확정**했다. `docs/preview-N.png`는 A 원본, `docs/preview-N-claude.png`는 B(그라데이션 배경 — 입력 박스 잘림·숫자 겹침 결함이 있어 폐기)다. 둘 다 임시 파일이고 최종본은 `assets/store/`이므로 `docs/`의 10장은 사용자 확인 후 삭제해도 된다.
- 1~3번은 A 원본을 그대로 쓰고 **4·5번만 새로 만들었다**(3·5절). 4·5번 합성 스크립트는 저장소에 없고 `%TEMP%\turncal-e2e`(`preview-a45b.mjs`, `compose-a.mjs`)에만 있다. 다시 만들 일이 있으면 5절 방법으로 새로 짠다.

## 1. 규격 (콘솔 입력 규칙)

| 종류 | 해상도 | 수량 | 비고 |
|---|---|---|---|
| 세로형 스크린샷 | **636 × 1048** | **최소 3장**, 최대 10장 | PNG/JPG, 5MB 이하 |
| 가로형 스크린샷 | 1504 × 741 | 최소 1장 | 가로·세로를 **섞을 수 없음** → 세로형만 쓴다 |
| 가로 썸네일(선택) | 1932 × 828 | 1장 | 콘솔 폼에는 입력칸이 없고, MCP로만 넣을 수 있음 |

- 해상도는 1px이라도 다르면 거부된다. 축소·압축·포맷 변환 없이 규격 크기 원본을 올린다.
- **세로형 5장**으로 간다(필수 3장 + 여유 2장). 가로형·썸네일은 만들지 않는다.
- 실제 앱 화면을 쓴다. 없는 기능을 보여 주거나 목업으로 과장하지 않는다(검수에서 앱 설명과 대조됨).

## 2. 공통 디자인 규칙

- **브랜드**: 대표색 인디고 `#4F46E5`, 연한 인디고 `#EEF2FF`. 토스 블루(`#3182F6`·`#0064FF` 계열)와 `Toss Product Sans` 금지.
- **라이트 전용**. 다크모드 화면을 쓰지 않는다.
- **구성**: 상단 문구 영역 약 25%(168px) + 아래 앱 화면 약 75%. 배경은 **흰색(`#FFFFFF`) 단색**(그라데이션 금지)에 문구만 `#191F28`, 보조 문구 `#6B7684`.
- **문구 규칙**: 한 장당 제목 1줄(18~20자 이내) + 보조 1줄. 이모지·과장 표현("최고", "1위")·타 서비스 비교 금지. 해요체 사용.
- **글자 크기**: 제목 32px(2x 기준, 실제 16px), 보조 24px(12px). 11px 미만 글자 금지.
- **광고**: 달력 하단 배너 영역은 스크린샷에 **넣지 않는다**(광고 노출을 홍보 이미지로 쓰지 않음). 촬영은 광고 없음 상태(`forceNoFill`)로 한다.
- **개인정보**: 가상의 이름·메모만 쓴다. 근무표 이름은 `내 근무표`, 이름은 `김턴캘`처럼 실존 인물이 아닌 값.

## 3. 장면 구성 (세로형 5장)

기준 데이터: 주간·오후·야간·비번·휴무를 조합한 7일 주기, 기준월 **2026년 10월**(개천절 10/3, 대체공휴일 10/5, 한글날 10/9가 한 달에 모두 보임). 오늘은 10/13.

| # | 제목 | 보조 문구 | 보여 줄 화면 | 강조할 요소 |
|---|---|---|---|---|
| 1 | 교대 근무를 한눈에 | 월간 달력에서 근무를 바로 확인해요 | 달력 화면(2026년 10월) | 근무 유형별 색·약어(주·오·야·비·휴), 오늘 표시, 공휴일 이름 |
| 2 | 순서만 정하면 자동 계산 | 반복 순서를 등록하고 오늘 위치만 골라요 | 근무 패턴 설정(근무 순서 + 오늘 위치) | 근무 순서 칩 목록, 오늘이 몇 번째인지 선택 |
| 3 | 날짜별로 메모도 남겨요 | 근무 시간과 세부 내용을 따로 적어요 | 날짜 화면(10/13 세부 내용 편집) | 근무 시간 입력, 메모, 그날 근무로 적용 |
| 4 | 주말·공휴일은 색과 이름으로 | 달력과 날짜 화면에 공휴일 이름이 보여요 | **위: 달력 첫 두 줄**(월 제목~개천절·대체·한글날) **+ 아래: 10/9 한글날 날짜 화면** | 개천절·대체·한글날 축약 이름, 날짜 화면의 빨간 공휴일 이름 |
| 5 | 화면은 내 취향대로 | 색 테마와 주 시작 요일을 바꿔요 | **위: 화면 설정**(딥 틸 선택됨 + 주 시작 요일) **+ 아래: 딥 틸 테마가 적용된 달력** | 테마 선택, 선택 결과가 달력에 반영된 모습 |

- 1번이 대표 이미지다(콘솔 목록에서 처음 보임). 가장 정보가 많고 앱 성격이 드러나는 달력 화면을 쓴다.
- 4번을 "달력 확대"로 하지 않은 이유: 앱 레이아웃에 **최소 폭(약 300 CSS px)**이 있어 270px 뷰포트로는 7열이 잘리고, 390px 폭 기준에서는 확대 여지가 없어 1번과 중복된다. 그래서 달력 윗부분과 공휴일 날짜 화면을 세로로 쌓았다(두 조각 사이는 `#F2F4F6` 14px 구분띠).
- 5번은 설정 화면만 두면 아래 20%가 빈 공간이 되므로, 선택한 테마가 적용된 달력을 아래에 붙였다.
- 설명(상세 설명)에 없는 기능은 넣지 않는다. 위 5장은 모두 상세 설명 본문에 있는 기능이다.

## 4. 장면별 와이어프레임 (636 × 1048)

```
┌──────────────────────┐ 0
│  제목 (32px, 굵게)      │
│  보조 문구 (24px)       │ 168
├──────────────────────┤
│ ┌──────────────────┐ │ 200
│ │ 앱 화면 (실제 캡처)   │ │
│ │ 폭 540, 둥근 모서리 24│ │
│ │ 아래는 화면 밖으로 잘림 │ │
│ │                    │ │
│ └──────────────────┘ │ 1048
└──────────────────────┘
```

- 앱 화면은 폭 540px(좌우 여백 48px)로 배치하고 하단을 프레임 밖으로 잘라 세로 공간을 채운다.
- 기기 베젤은 그리지 않는다. 연한 회색 테두리(`#E5E8EB`, 2px)와 둥근 모서리로 화면 경계만 표시한다.
- 상태 표시줄·내비게이션 바는 토스 앱 형태가 그대로 보이지 않게, 앱 화면 영역(콘텐츠)만 캡처해 쓴다.

## 5. 촬영·제작 방법

1. `npm run dev`(AIT Devtools mock 포함)를 켜고, `scripts/e2e/README.md`의 방식대로 헤드리스 Edge(Playwright)로 조작한다. 광고는 `window.__ait.patch("ads", { forceNoFill: true })`로 끈다.
2. 저장값은 `localStorage`의 `__ait_storage:` 접두어 키로 직접 넣는다(근무 주기·기준일·이름·세부 내용). 기준 시각은 2026-10-13으로 고정한다.
3. 뷰포트 **CSS 390 × 844, deviceScaleFactor 540/390**(≈1.385)로 캡처해 폭이 정확히 540px이 되게 한다. 270px 같은 좁은 뷰포트는 최소 폭 때문에 오른쪽이 잘리니 쓰지 않는다. 4·5번은 `page.screenshot({ clip })`으로 필요한 구간만 자른다(달력 구간 하단은 다음 줄의 오늘 선택 테두리가 걸리지 않게 셀 아래 경계에서 약 4px 안쪽으로 자른다). 시계는 `page.clock.setFixedTime(2026-10-13T10:00+09:00)`로 고정하고, `history.back`을 무력화하며 `.ait-panel-toggle`을 숨긴다.
4. 캡처한 PNG를 제목·보조 문구와 합성해 636 × 1048로 내보낸다. 합성은 HTML 한 장(흰 배경, 제목 34px·보조 24px, 앱 화면 틀 left 48·top 200·폭 540·`2px #E5E8EB` 테두리·위쪽 모서리 28px)을 렌더링해 스크린샷하면 해상도 오차 없이 규격 크기로 나온다. 조각을 쌓을 때는 폭 536px 이미지를 틀 안에 순서대로 넣는다.
5. 출력 파일은 `assets/store/preview-1.png` ~ `preview-5.png`(`assets/logo.png` 옆)에 둔다. 현재 이 5장이 들어 있다.
6. 업로드 전에 5장 모두 정확히 636 × 1048인지 확인한다(파일 크기 5MB 이하).
